# PPO

Proximal Policy Optimization：近接方策最適化
OpenAIによって提案された深層強化学習の代表的なアルゴリズム

## 概要

従来の方策勾配法には、方策を一度に更新しすぎると、性能が致命的に崩壊して回復しなくなるという欠点があった。
この問題を解決するためにTRPOが提案された。これは更新前後の変化量を信頼領域内に制限することで安定性を確保する手法だが、計算にヘッセ行列や共益勾配法などを要求し、実装が複雑で計算負荷が重かった。

PPOは、TRPOの「更新幅を制限して学習を安定させる」というメリットを保ちながら、一回微分だけで扱えるシンプルなクリップ機構に落とし込んだ手法。

## 用意するもの

* Actor/Criticを担当するNNモデル
    * Actorモデル: 状態sを受け取り、行動の確率分布のパラメータを返す
    * Criticモデル: 状態sを受け取り、その状態自体の価値を表すスカラー値を1つだけ出力する
* ロールアウトバッファ
    * 現在の方策ごとに用意される、専用の短期データバッファ
    * 状態、選択した行動、行動の対数確率、即時報酬、終了フラグ、状態価値推定値、を保存しておく。
    * 環境とのステップで収集され、並列化された環境で数百から数千ステップ分となる。
* 各種ハイパーパラメータ

Actor/Criticは、完全に別のモデルを利用することも、バックボーンを共有して出力層だけ分離することもできる

## やること

### 学習ループ

#### ロールアウト

各環境で決めた固定ステップ数(Tステップ、128-2048など)だけ環境を進め、バッファを埋める。この間、勾配計算はオフにする。

各タイムステップtごとに、次の手順を踏む。

1. 現在の状態sをactorとcriticに入れる
    * actorではその出力から行動を出力するための確率分布を構築し、行動をサンプリングする。この時、必ずサンプリングした行動の対数確率を保存しておく。
    * criticでは現在の状態価値をスカラー値として計算、保存する。
2. 環境の実行を環境に渡し、即時報酬、次の状態、終了フラグを受け取る。
3. 取得された次の情報をまとめ、1つ分のデータ一式として保存する。
    * 状態
    * 行動
    * サンプリングした行動の対数確率
    * 即時報酬
    * 終了フラグ
    * 現在の状態価値

以上をTステップ分行う。N個の環境を並列に動作させる場合は、 $ N \times T $ 個のデータを得ることができる。

#### アドバンテージ(GAE)の計算

Tステップのデータ収集が終わったら、GAEを用いてアドバンテージを計算する。アドバンテージは「状態の平均的な期待値よりどれだけ優れていたか」を示す。その計算方法としてGAEを利用する。

アドバンテージの計算方法は、他にも次のようなものが考えられるが、それぞれ欠点がある。

* 1ステップTD誤差 $\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$
    * 分散は小さいが、$V(s_{t+1})$ の予測精度に依存し、バイアスが大きい
* モンテカルロ法(将来の割引報酬合計 $R_t - V(s_t)$)
    * 実際の報酬を利用するのでバイアスはないが、期間が長くなるほど確率的なブレが増加し、分散が非常に大きい

GAEは、これら2つの指標を $ \lambda $で線形補間し、適度にバイアスを抑えつつ、分散も抑える、というバランスをとる。

計算は、時系列を未来から過去の方向に、逆向きにループさせて計算する。

1. 各時刻の基本となるTD誤差を求める
    * $\delta_t = r_t + \gamma V(s_{t+1})(1 - done_{t+1}) - V(s_t)$
    * エピソード終了なら、未来の価値を0にマスク
2. GAEによるアドバンテージの再起的計算
    * $\hat{A}_t = \delta_t + (\gamma \lambda) (1 - done_{t+1}) \hat{A}_{t+1}$
    * $\lambda = 0$ のとき：$\hat{A}_t = \delta_t$（単純な1ステップTD誤差）
    * $\lambda = 1$ のとき：割引累積報酬から価値ベースラインを引いたもの（モンテカルロ法）
    * 通常は $\lambda = 0.95$ とし、数ステップ先までのTD誤差を適度な重み付き和で反映する。
3. Critic更新用のターゲット価値 $V_t^{\text{targ}}$ の算出
    * アドバンテージ = 実際の価値 - ベースライン $ V(s_t) $ なので、ターゲットリターンを逆算する
    * $V_t^{\text{targ}} = \hat{A}_t + V(s_t)$

#### アドバンテージの正規化

バッファ全体の全ステップ（$T \times N_{\text{envs}}$ 個）についてアドバンテージが計算できたら、更新に回す直前に平均0・分散1に正規化する。

$$\hat{A}_t \leftarrow \frac{\hat{A}_t - \text{mean}(\hat{A})}{\text{std}(\hat{A}) + 10^{-8}}$$

> ここでアドバンテージの正規化 -> ターゲット価値の算出 としてはいけない。それだとターゲットリターンにスケールの違う値が混ざり、学習が崩壊する。

#### データの平坦化とミニバッチ分割

環境とステップ数を平坦化し、全サンプルを1次元に並び替える。

その後、設定したエポック数だけ、データをランダムにシャッフルし、ミニバッチサイズごとに取り出してネットワークに入力する。

> DQNでは「過去のあらゆる経験データ」が混ざった巨大なバッファから無作為に取り出すが、PPOは「直前の方策が作った最新データセット」全体を複数エポック学習させる

#### 損失関数の計算とパラメータ更新

各ミニバッチのデータ（状態 $s_t$、行動 $a_t$、収集時の対数確率 $\log \pi_{\theta_{\text{old}}}$、正規化済みアドバンテージ $\hat{A}_t$、ターゲットリターン $V_t^{\text{targ}}$）を最新のネットワークに入力し、3つの損失を計算する。

最新のネットワークから得られる値：
- $\log \pi_\theta(a_t \mid s_t)$：最新のActorによる該当行動の対数確率
- $\mathcal{H}(\pi_\theta(\cdot \mid s_t))$：最新のActorが出力する確率分布のエントロピー
- $V_\phi(s_t)$：最新のCriticが予測する状態価値

1. Actor損失（Clipped Surrogate Objective）
- 新旧方策の確率比 $r_t(\theta)$ を計算する。数値安定性のため対数確率の差から指数を取る。
$$r_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_{\text{old}}}(a_t \mid s_t)} = \exp\left(\log \pi_\theta(a_t \mid s_t) - \log \pi_{\theta_{\text{old}}}(a_t \mid s_t)\right)$$
- 確率比を $[1-\epsilon, 1+\epsilon]$（通常 $\epsilon = 0.1 \sim 0.2$）の範囲にクリップし、クリップなしの項との最小値（$\min$）を取る。
$$\mathcal{L}^{\text{Actor}}(\theta) = - \hat{\mathbb{E}}_t \left[ \min\left( r_t(\theta)\hat{A}_t, \, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t \right) \right]$$
- $\hat{A}_t > 0$（良かった行動）なら、比率が $1+\epsilon$ を超えた段階で目的関数が頭打ちになり、確率の過剰な引き上げを防ぐ。
- $\hat{A}_t < 0$（悪かった行動）なら、比率が $1-\epsilon$ を下回った段階で勾配がカットされ、過剰なペナルティによる方策の崩壊を防ぐ。
- 最小値（$\min$）を取ることで、有利に見積もりすぎている更新にブレーキをかけ、常に悲観的（安全側）に評価する。

2. Critic損失（Value Loss）
- 逆算しておいた正解ラベル $V_t^{\text{targ}}$ に対する二乗誤差（MSE）を計算する。
$$\mathcal{L}^{\text{Critic}}(\phi) = \frac{1}{2} \hat{\mathbb{E}}_t \left[ \left( V_\phi(s_t) - V_t^{\text{targ}} \right)^2 \right]$$
- 実装によっては、Actor同様にCriticの予測値も古い推定値 $V_{\text{old}}(s_t)$ から急激に離れないようクリップした値との $\max$ を取る場合もある。

3. エントロピー損失（Entropy Bonus）
- 方策が特定の行動に早期収束（過度な決定論化）して探索を放棄するのを防ぐための項。
$$\mathcal{L}^{\text{Entropy}}(\theta) = - \hat{\mathbb{E}}_t \left[ \mathcal{H}(\pi_\theta(\cdot \mid s_t)) \right]$$
- 確率分布の乱雑さ（エントロピー）が大きいほどボーナスを与えたい（最大化したい）ため、損失としては負の符号をつける。

4. 全体損失の統合と逆伝播
- 3つの損失を係数 $c_1$（通常 $0.5$）および $c_2$（通常 $0.01$）で重み付けして合算する。
$$\mathcal{L}_{\text{total}} = \mathcal{L}^{\text{Actor}}(\theta) + c_1 \mathcal{L}^{\text{Critic}}(\phi) + c_2 \mathcal{L}^{\text{Entropy}}(\theta)$$
- バックボーンを共有している場合、この1つの損失から逆伝播することで、方策改善と価値推定の両方の勾配をバランスよく共通層へ流し込める。
- `loss.backward()` の後、勾配爆発を防ぐために 勾配クリッピング（L2ノルムを0.5以下に制限） を行い、パラメータを更新する。

#### バッファの破棄と次のサイクルへ

設定したエポック数（$K$ 周）のミニバッチ学習がすべて終了したら、収集したロールアウトバッファのデータを完全に破棄（上書き）する。

パラメータが更新されたことで、手元のデータはすでに「過去の方策が生成した古いデータ」となっており、これ以上使い回すとオンポリシーの前提が崩れるためである。

新しくなった方策 $\pi_\theta$ を用いて、再び最初の「ロールアウト」から次のサイクルを開始する。
