# DQN

## 概要

Deep Q-Network
価値関数をNNによって近似し、そのNNの最適化方法を提供する。
行動空間に上限がある -> 可能な行動の数が有限個である 環境にのみ利用できる。

Q学習という、有限状態かつ有限行動の環境に対して利用可能な教科学習アルゴリズムがあるが、DQNはそれを深層学習に適応できるように拡張したもの。

Q値 = 「ある状態のときに、特定の行動をとったら、その先（ゲーム終了まで）トータルでどれくらいの報酬を獲得できそうか」で、これを改善し続ける。

## 用意するもの

整理すると以下の通り

* 価値関数を近似するためのNNモデル
    * 入力は、バッチ処理された状態s(形状[B, state_shape])
    * 出力は、バッチ処理された各行動の価値a(形状[B, action_num])
    * 出力は活性化関数をかける前の値であることが要求される。値域は実数全体である。
* 最適化器
* リプレイバッファ
* ガンマ: 割引率。ベルマン方程式の計算に利用される。
* 探索の制御パラメータ
    * 開始イプシロン: 探索率の初期値
    * 終了イプシロン: 探索率の下限
    * 減衰率: ステップごとにどれだけ減らすか
* 学習制御・更新ルール
    * バッチサイズ
    * ターゲット更新インターバル: ハード同期の際、**勾配更新を何回行うごとに**ターゲットネットワークを全コピーするか（環境ステップではない）
    * 混合率: ソフト同期の際、どのくらいの割合で重みを混ぜるか

## やること

### 前準備

メインネットワークをコピーしてターゲットネットワークを作成する。
これは通常の誤差逆伝播法によるパラメータ更新を行わない。

またリプレイバッファを確保する。

### 学習ループ

#### 1. 行動選択フェーズ(epsilon-greedy法)

現在の状態sに対して、エージェントは「探索」と「活用」のバランスをとり、行動aを決定する。
* 確率epsilopnで: ランダムな行動を選択する
* 確率1-epsilonで: メインネットワークの予測Q値が最大となる行動を選択する

学習が進むにつれてeisilonは徐々に減衰させ、初期はランダム探索を多く、後半ほど少なくする。

#### 2. 環境との相互作用と経験の蓄積

決定した行動aを環境に渡し、即時報酬r、次の状態s'、終了判定doneを受け取る。
この1つの遷移データ(s, a, r, s', done)をそのままリプレイバッファに追加する。
リプレイバッファは、いっぱいになったら古い方から順に破棄する。

#### 3. ミニバッチサンプリング

バッファ内に十分な量のリプレイ(通常はバッチサイズ以上)が溜まったら、ランダムにB件の遷移を取り出す。
取り出すといっても、バッファ内からは削除されず、コピーされるだけ。
> ランダムなのは、連続しているリプレイデータは似ているものが多い(自己相関性が高い)ので、ランダムに取り出すことでデータをシャッフルし、NNが均一に学習できるようにするため

#### 4. メインネットワークの更新

取り出したバッチデータを用いて、「現在の予測値」と「正解とみなす目標値」のずれを計算する。

まず、バッチデータから状態sと実際にとった行動aを取り出して、メインネットワークに入力する。
これが現在の予測Q値である。

次に、バッチデータから次の状態s'を取り出して、ターゲットネットワークに入力し、全行動の中で最も出力値が高い行動を選んだ場合の出力値を得る。
そしてその値を用いて将来価値を割引加算する。

$$y = r + \gamma (1 - \text{done}) \max_{a'} Q(\mathbf{s}', a'; \boldsymbol{\theta}^-)$$

これが目標Q値である。

最後に、二乗誤差(または外れ値に強いHuber損失)を計算し、メインネットワークの重みのみを誤差逆伝播法で更新する。

#### 5. ターゲットネットワークの同期

メインネットワークの更新に合わせて、ターゲットネットワークを追従させる。

* ハード同期の場合: 一定ステップごとにターゲットネットワークをメインネットワークで上書きする。
* ソフト同期の場合: 毎ステップ、微小な割合tauで少しずつ線形補間更新

### 注意点

#### リプレイバッファからバッチデータを取り出すタイミングは？

多くの場合、リプレイバッファに1件加わったら(=環境が1ステップ進んだら)で、今回はこれを採用する。
ただし学習ループに入る前に、十分な数のリプレイをリプレイバッファに追加しておく

## 派生アルゴリズム

DQNには、その問題を解決するために、いくつか派生系が存在する。

### DDQN(Double DQN)

Q値の計算方法の変更

DQNでは全ての行動の候補から、ターゲットネットワークにおいて最もよく評価された行動をそのままQ値としていたが、これではQ値を過大に解釈してしまう可能性がある。DDQNは、ターゲット値の計算において、行動の選択をメインネットワークで、その評価をターゲットネットワークで行うというもので、選択と評価を独立させることで、不正な過大評価を避けることができる。

メインネットワーク更新の目標 Q 値のみが異なる。行動選択・リプレイ・ターゲット同期は DQN と同じ。

次の状態 $\mathbf{s}'$ について、メインネットワークで greedy 行動 $a^* = \arg\max_a Q(\mathbf{s}', a; \boldsymbol{\theta})$ を選び、ターゲットネットワークでその行動の Q 値を読む。

$$y = r + \gamma (1 - \text{done}) \, Q(\mathbf{s}', a^*; \boldsymbol{\theta}^-)$$

ここで $a^* = \arg\max_a Q(\mathbf{s}', a; \boldsymbol{\theta})$（選択は $\boldsymbol{\theta}$、評価は $\boldsymbol{\theta}^-$）。


### PER(Prioritized Experience Replay)

リプレイバッファのサンプリング方法の変更

通常のDQNにおけるバッファからの遷移データの抽出(一様サンプリング)を、重み付けされた確率サンプリングに変更する。

重み付けにあたって利用するのは、TD誤差(Temporal Difference Error)である。TD誤差とは

$$\delta_i = R_{t+1} + \gamma \max_{a'} Q(S_{t+1}, a'; \boldsymbol{\theta}^-) - Q(S_t, A_t; \boldsymbol{\theta})$$

の式で表され、(実際に行動して得られた報酬) - (現在の予測)を示す。
TD誤差が

* 正 -> 嬉しい誤算。思っているよりも価値の高い行動だったので、上方修正する。
* 負 -> 痛い失敗。思っているよりも価値の低い行動だったので、下方修正する。
* 0 -> 予想通り。修正の必要なし

つまりTD誤差の絶対値が大きい -> その行動を学ぶ価値が高い。になる。

なのでTD誤差の絶対値が大きいものほどサンプリングされやすいように重み付けする。重み付けの強さはハイパーパラメータとして $\alpha$ で制御でき、0なら一様サンプリング、1なら完全比例した重みづけとなる。

ただし、ただサンプリングすると、データ分布の期待値が本来の環境の期待値からずれてしまい、推定にバイアスがかかる。

これの補正のため、損失関数の計算時に重要度サンプリングの重みを各サンプルに乗算する。

$$w_i = \left( \frac{1}{N} \cdot \frac{1}{P(i)} \right)^\beta$$

ここでNは現在のバッファサイズである。数値の安定性のため、ミニバッチ内の最大重みで正規化して用いる。

$$w_i \leftarrow \frac{w_i}{\max_j w_j}$$

式中に登場した $\beta$ はハイパーパラメータであり、0で全く無補正、1で完全に補正する。
学習の序盤はバイアスを許容して学習を進め、終盤は正確な期待値推定を学習させたいので、開始時点は $\beta=0.4$程度として、**勾配更新回数**に応じて1.0まで線形増加させる手法が取られる（本リポジトリの CartPole ではアニーリング長に `run.max_env_steps` を runner が渡す）。

損失関数は、通常の二乗誤差やHuber損失に対して重みを乗算した形になる

$$\mathcal{L}_{\text{PER}} = \frac{1}{B} \sum_{i=1}^{B} w_i \cdot L(\delta_i)$$

なお、バッファ全体に対して優先度を計算しサンプリングするのは時間がかかるので、SumTreeというデータ構造を用いる。

### Dueling DQN

モデルアーキテクチャの変更

「行動がどうでもいい場面」の無駄をなくすため、Q値を「状態そのものの価値」と「行動の相対的な優位性」の2つに分解する。

* $V(s)$ = 状態価値：その状態にいること自体がどれくらい有利かのスカラー値。行動に依存しない。
* $A(s, a)$ = アドバンテージ：その状態においてある行動をとることが平均的な手と比べてどれくらい優れているかの相対値

そしてそれぞれを計算するために、最後の出力前に2系統の全結合層を用いて計算し、統合してQ値の出力とする。

具体的な実装としては、出力の直前にある全結合層(各行動のQ値を計算する層)を、2系統の全結合層に差し替える。

* 全結合層V(出力次元=1)
* 全結合層A(出力次元=行動の数)

そして2つの出力値を

$$Q(s, a) = V(s) + \left( A(s, a) - \frac{1}{\vert{}\mathcal{A}\vert{}}\sum_{a'} A(s, a') \right)$$

として、Q値の計算とする。

それ以外のコンポーネントは変わらない。モデルアーキテクチャのみの変更である。

本リポジトリでは Dueling を別 `algorithm` 名にせず、実験 YAML の `hyperparameters.qnet_type: dueling`（省略時 `mlp`）で Q ネットを差し替える。CartPole の構築は `tasks/01_CartPole/models.py`。実装メモは [`implementation.md`](implementation.md)。
